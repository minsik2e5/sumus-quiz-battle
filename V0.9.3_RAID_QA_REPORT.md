## Architecture

- `client/raid-domain.js`: serializable RAID state, timing table, damage, combo, shield, DOWN/REVIVE, GUARD, HEAVY, mercy support, wave planner.
- `client/raid-mode.js`: RAID-only adapter over the existing Quiz/Room/Student/Teacher flow, authoritative teacher timestamps, reconnect snapshots, student HUD, teacher Spotlight/cards/log/results.
- RUN remains delegated to the existing RaceEngine path. RAID state lives under `player.raid`, never in distance/worldDistance.
- LISTEN begins its eight-second attack window after speech playback ends.
- Teacher-owned authoritative state is cached by the existing room registry and restored after teacher refresh. Student snapshots include HP, enemy HP, combo, wave, shield, active question, deadline, and timeout state.

## Known limitations / V0.9.3B recommendations

- The authoritative clock currently follows the existing teacher-owned authoritative state rather than moving combat simulation into a new backend service. This is intentional for the smallest network change; a later server-hosted timer worker could harden teacher-offline continuity.
- Character/monster art is an emoji/CSS fallback behind a replaceable presentation boundary.
- Early clear ends that student's combat immediately. A later version can add a clearly defined bonus-study flow for remaining questions.
- Add richer retry-battle result presentation, long-term forgetting strength, asset animation packs, and expanded Spotlight event tuning in V0.9.3B.
