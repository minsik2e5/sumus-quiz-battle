## 1. 측정 조건과 해석할 때 주의
- 세로 폰 390×844 · 배율 3 · 터치, CPU 1× · 4×(자동 품질) · 6×(대행진 · 아레나는 최저 고정). 조건마다 3번의 중간값.
- 이 컨테이너는 캔버스 · 화면을 CPU로 그리고, 예전 측정 기계보다 느립니다. 대행진 6× 최저가 CHANGES_v13.241.0의 58.9fps가 아니라 **약 43fps**로 나옵니다. 절대 숫자를 예전 문서와 비교하지 말고, 같은 기계에서 잰 전 · 후만 비교합니다.
- 빈 화면(일 없는 rAF)은 6×에서도 60fps입니다(`scripts/blank.mjs`). 손실은 게임 프레임에서 납니다.
- **측정 두 개를 동시에 돌리면 숫자가 망가집니다.** 대행진 기준 측정 1 · 2번째 pass 일부가 그렇게 오염됐습니다(over50이 330~380/분으로 튄 값). 중간값은 쓸 만하지만 표에 따로 적었습니다.
- 터치 탭의 입력 지연 p95 50~65ms(짝 맞추기 · 벽 통과 · 가위바위보 · 야바위)는 1×에서도 같아서, Playwright가 만든 터치의 지연으로 봅니다(키보드로 누르는 게임은 11~16ms). 게임 문제로 판정하지 않았습니다.

## 3. 찾은 원인
확인된 것(측정 · 트레이스 근거, `trace-*.txt`):
1. **낚시**: 낚싯대 SVG 요소 40~50개를 매 프레임 innerHTML로 새로 만들었습니다(`drawRig`). 트레이스에서 배치 무효화 1139번이 이 줄, ParseHTML 1.4초/30초.
2. **짝 맞추기**: 시계 글자를 매 프레임 써서 배치가 프레임마다 다시 됩니다(`tick` 800번). 50ms 넘는 프레임 자체는 카드를 맞힌 순간(이벤트 처리 43~59ms)과 라운드가 바뀔 때(타이머 49ms)입니다.
3. **인형뽑기**: 집게 위치를 left · top · width(%)로 매 프레임 써서 배치(`drawClaw` 289번), 판 중 그림 디코드 274ms/18초, 커밋 44ms 한 번.
4. **아레나**: 혼자 판 4×에서 느린 프레임은 (가) 판 시작 0.6초 · 1.0초의 550 · 383ms(입장 꾸미기), (나) 4.4초 품질 단계가 내려가는 순간 117ms, (다) 27.7~28.0초 펫 교체 때 100 · 133ms. (다)는 `setPet` → `build`가 본체 · 실루엣 · 테두리 · 자세 스프라이트를 한 프레임에 굽기 때문으로 **추정**합니다(코드로만 확인).
5. **10초 맞추기 · 가위바위보 · 야바위**: 긴 프레임은 결과 · 배너가 뜨는 순간 한 번입니다.

추정(재지 못함): 벽 통과 피버 테두리(`wl-fever`) · 가위바위보 긴장 테두리(`rps-vig`)의 화면 전체 box-shadow 애니메이션, 인형뽑기 반짝이(`cw-glit`)의 background-position 애니메이션, 야차전 콤보 빛(`fx2-aura`)의 filter 애니메이션. 대행진에서 늦게 도착한 그림마다 판 중에 다시 굽는 것(runner.js `warmArt` 1.8초 제한 뒤). 낚싯대 그림자 필터는 꺼도 차이가 없었습니다(`x-fish.jsonl`: 50ms↑ 12 → 8.9/분, 범위 겹침).

## 7. 주의할 점
- 판마다 서버를 새 데이터로 다시 켜야 합니다(하루 횟수: 10초 맞추기 3판, 가위바위보 · 야바위 5판 등). ts2 계정만 대행진 99스테이지가 열려 있습니다.
- 첫 화면의 앱 설치 배너가 놀이터 카드를 가립니다. `game-perf.mjs`가 닫지만, 탭 전환 첫 누름이 가끔 묻혀 재시도를 넣었습니다.
- `game-perf.mjs`의 야차전 · 몬스터는 한 판이 120초라 창(30초) 안에 끝나지 않습니다. "나간 뒤" 숫자는 `--seconds 140`으로 끝까지 가야 의미가 있습니다.
- CSS는 `server/build-assets.mjs`의 목록에 `v13246.css` 한 줄을 넣었고, CSS를 고치면 `npm run build:assets`를 돌려야 화면에 반영됩니다(sw.js도 바뀜).
- 규칙 · 서버 판정 파일(arena-rules · arena-live-rules · runner-rules · server 판정)은 건드리지 않았습니다. 운영 Supabase에 연결한 적 없습니다.
