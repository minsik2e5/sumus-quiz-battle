# 10초 맞추기 — 멈춤 현상 · 오늘의 챌린지 · 고스트 설계

## 1. 멈춤 현상(V13.191)

선생님: "지금 마지막에 눌렀을 때 몇 초 더 갔다가 멈추는 현상이 있어."
재현: 로컬 서버(sqlite) + Playwright(크롬, 390×844). 화면 숫자판의 `aria-label`이 바뀔 때마다 시각을 남겨 누른 뒤 숫자가 어떻게 움직이는지 봤다.

| 원인 후보 | 재현 조건 | 보인 현상(고치기 전) | 결론 |
|---|---|---|---|
| (a) 공개 연출이 숫자를 거꾸로 셈 | 숨김 중 9.80초에 스페이스 | 누르자마자 **9.31**이 나오고 1.41초 동안 85번 숫자가 올라가 9.80에서 멈춤 | **주원인.** "누른 뒤 더 갔다가 멈춘다"가 정확히 이 모습 |
| (a′) 숨김 전에 누름 | 2.50초(숫자가 보일 때)에 누름 | 2.47 → **1.99**로 0.5초 뒤로 갔다가 2.49까지 다시 올라감 | 같은 원인 |
| (b) 서버 값으로 덮어쓰기 | 끝 신호만 0.3초 / 0.7초 늦게 | 9.80에 눌렀는데 결과 숫자 **10.09 / 10.48** | **원인.** 느린 와이파이에서 결과가 "누른 것보다 크다" |
| (b′) 시작 쪽만 느림 | 시작 신호 0.4초 늦게 | 결과 **9.40**(더 작아짐) | 같은 원인(방향은 지연 차이에 따라) |
| (c) 이벤트 시각 기준(`stampOf`) | 메인 스레드 0.4초 막힘(저사양 폰 버벅임) 중 누름 | 이벤트 시각이 378ms 앞이라 250ms 제한에 걸려 처리 시각을 씀: 9.82 → **10.19** | **원인.** 버벅이는 폰에서 결과가 크다 |
| (c′) 낮은 프레임 rAF | CPU 6배 느리게 | 누른 뒤 달리기 프레임이 더 돌지 않음(누르면 먼저 멈춤) | 문제 없음 |

고친 뒤(같은 조건): 모든 경우 누른 뒤 숫자 변화 **1번**(누른 값으로 바로 멈춤), 0.7초 지연에서도 9.81 그대로, 버벅임 0.4초에서도 9.82.

### 고친 방법
- **공개 연출**: 숫자는 누른 순간 멈춘 값으로 한 번만 그린다. 슬로모션 느낌은 그대로 1.4초, 표현만 빛으로 바꿨다: 무대가 어두워지고 숫자판이 커진 채(기존), 네온이 켜지듯 켜짐 · 꺼짐 깜빡(째깍 5번, `REVEAL_STEPS`) + 빛줄기가 숫자판을 훑고 → 번쩍 + 공개 소리(기존). 움직임 줄이기면 깜빡 · 빛줄기 없이 바로.
- **서버 측정과 다를 때**: 화면 숫자 · 오차 · 등급은 **누른 값 그대로**. 그 판은 코인 0 · 순위 · 기록 · 칭호에서 빠지고, 경험치만 서버가 잰 시간 등급으로. 안내 "인터넷이 느려서 이번 판은 코인 · 순위 · 기록에서 빠졌어요. 숫자는 누른 그대로예요." 선생님 활동 기록에는 "… · 인터넷 느림(서버 +0.48초, 기록 제외)".
- **누른 시각**: 같은 시계의 이벤트 시각이면 1초 안까지 믿는다(250ms → 1초).

### 부정 방지의 한계
- 예전: 허용 오차를 벗어나면 서버 시간으로 판정하고 코인은 좋음(8)까지. 지금: 벗어나면 **코인 0**(더 엄격). 부정으로 얻는 것은 자기 화면에만 보이는 숫자뿐.
- 허용 오차 안(±0.15초 + RTT/2)의 값을 속이는 부정은 예전과 같이 막지 못한다(하루 상한 · 운 감시로 묶음).
- 정직한 학생도 끝 신호가 0.15초 넘게 늦으면(와이파이 순간 끊김, 0.4초 넘는 버벅임 뒤에 보낸 경우) 그 판 코인을 못 받는다. 숫자는 정확하게 보이고 안내가 뜬다.

## 검사(server/timing-check.mjs)
- 공개 연출 모든 프레임(60 · 30 · 20fps)에서 보이는 숫자 = 멈춘 값(정지값보다 커지는 프레임 없음)
- 누른 시각 규칙(1초 안 이벤트 시각, 미래 · 다른 시계 · 없음은 처리 시각)
- 서버 측정과 다를 때: 숫자 · 오차 = 보낸 값, 코인 0, 순위 · 기록 제외, 경험치는 서버 측정, 활동 기록 문구
- 화면 코드: 누르면 프레임 먼저 멈춤, 서버 응답으로 숫자를 바꾸지 않음
