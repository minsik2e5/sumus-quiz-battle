# 10초 맞추기 — 멈춤 현상 · 오늘의 챌린지 · 고스트 설계

## 1. 멈춤 현상(V13.191)

선생님: "지금 마지막에 눌렀을 때 몇 초 더 갔다가 멈추는 현상이 있어."
재현: 로컬 서버(sqlite) + Playwright(크롬, 390×844). 화면 숫자판의 `aria-label`이 바뀔 때마다 시각을 남겨 누른 뒤 숫자가 어떻게 움직이는지 봤다.

| 원인 후보 | 재현 조건 | 보인 현상(고치기 전) | 결론 |
|---|---|---|---|
| (a) 공개 연출이 숫자를 거꾸로 셈 | 숨김 중 9.80초에 스페이스 | 누르자마자 **9.31**이 나오고 1.41초 동안 85번 숫자가 올라가 9.80에서 멈춤 | **주원인.** "누른 뒤 더 갔다가 멈춘다"가 정확히 이 모습 |
| (a′) 숨김 전에 누름 | 2.50초(숫자가 보일 때)에 누름 | 2.47 → **1.99**로 0.5초 뒤로 갔다가 2.49까지 다시 올라감 | 같은 원인 |
| (b) 서버 값으로 덮어쓰기 | 끝 신호만 0.3초 / 0.7초 늦게 | 9.80에 눌렀는데 결과 숫자 **10.09 / 10.48** | **원인.** 느린 와이파이에서 결과가 "누른 것보다 크다" |
| (b′) 시작 쪽만 느림 | 시작 신호 0.4초 늦게 | 결과 **9.40**(더 작아짐) | 같은 원인(방향은 지연 차이에 따라) |
| (c) 이벤트 시각 기준(`stampOf`) | 메인 스레드 0.4초 막힘(저사양 폰 버벅임) 중 누름 | 이벤트 시각이 378ms 앞이라 250ms 제한에 걸려 처리 시각을 씀: 9.82 → **10.19** | **원인.** 버벅이는 폰에서 결과가 크다 |
| (c′) 낮은 프레임 rAF | CPU 6배 느리게 | 누른 뒤 달리기 프레임이 더 돌지 않음(누르면 먼저 멈춤) | 문제 없음 |

고친 뒤(같은 조건): 모든 경우 누른 뒤 숫자 변화 **1번**(누른 값으로 바로 멈춤), 0.7초 지연에서도 9.81 그대로, 버벅임 0.4초에서도 9.82.

### 고친 방법
- **공개 연출**: 숫자는 누른 순간 멈춘 값으로 한 번만 그린다. 슬로모션 느낌은 그대로 1.4초, 표현만 빛으로 바꿨다: 무대가 어두워지고 숫자판이 커진 채(기존), 네온이 켜지듯 켜짐 · 꺼짐 깜빡(째깍 5번, `REVEAL_STEPS`) + 빛줄기가 숫자판을 훑고 → 번쩍 + 공개 소리(기존). 움직임 줄이기면 깜빡 · 빛줄기 없이 바로.
- **서버 측정과 다를 때**: 화면 숫자 · 오차 · 등급은 **누른 값 그대로**. 그 판은 코인 0 · 순위 · 기록 · 칭호에서 빠지고, 경험치만 서버가 잰 시간 등급으로. 안내 "인터넷이 느려서 이번 판은 코인 · 순위 · 기록에서 빠졌어요. 숫자는 누른 그대로예요." 선생님 활동 기록에는 "… · 인터넷 느림(서버 +0.48초, 기록 제외)".
- **누른 시각**: 같은 시계의 이벤트 시각이면 1초 안까지 믿는다(250ms → 1초).

### 부정 방지의 한계
- 예전: 허용 오차를 벗어나면 서버 시간으로 판정하고 코인은 좋음(8)까지. 지금: 벗어나면 **코인 0**(더 엄격). 부정으로 얻는 것은 자기 화면에만 보이는 숫자뿐.
- 허용 오차 안(±0.15초 + RTT/2)의 값을 속이는 부정은 예전과 같이 막지 못한다(하루 상한 · 운 감시로 묶음).
- 정직한 학생도 끝 신호가 0.15초 넘게 늦으면(와이파이 순간 끊김, 0.4초 넘는 버벅임 뒤에 보낸 경우) 그 판 코인을 못 받는다. 숫자는 정확하게 보이고 안내가 뜬다.

## 2. 오늘의 챌린지(V13.192)

하루에 하나의 목표 시간(예: 7.77초 · 5.00초 · 12.34초)으로 같은 학년대가 겨룹니다. 10.00초 기본 모드는 그대로 둡니다.

| 규칙 | 값 |
|---|---|
| 목표 시간 | 0.50 ~ 30.00초, 0.01초 단위 |
| 숫자 보임 | 처음부터 가림 · 1 · 2 · 3 · 5초(목표보다 짧게) |
| 판 수 | 하루 **1판**(10.00초 기본 판 3 ~ 5판과 따로) |
| 등급 | 오차 기준 그대로(완벽 ±0.05 · 훌륭 ±0.15 · 좋음 ±0.4 · 아쉬움 ±1초), 딱 맞추면 "딱 7.77!" |
| 너무 빠름 | 2초 또는 목표의 40% 중 짧은 쪽보다 빨리 누르면 실수(0.5초 챌린지는 0.2초) |
| 판 만료 | 60초 또는 목표 × 2 + 18초 중 긴 쪽(30초 챌린지도 끝까지 됨) |
| 서버 시간 확인 · 운 감시 | 기본 판과 같음(못 믿은 판은 숫자 그대로 · 코인 · 순위 · 기록 제외) |

### 선생님 설정 화면
- 위치: 선생님 **대시보드 위쪽 버튼 "🎯 오늘의 챌린지"**(PC, "보상 이벤트" 옆). 폰에서는 대시보드 맨 위 입구 카드(학습 보상 이벤트 카드 아래). 둘 다 같은 설정 창을 엽니다.
- 설정 창: 날짜(오늘 ~ 13일 뒤) · 목표 시간(초, 자주 쓰는 값 3.33 · 5.00 · 7.77 · 10.00 · 12.34 · 15.00 버튼) · 숫자 보임 · 한 줄 메시지(30자) · [자동으로] [저장]. 아래에 14일 목록(정함 · 자동, 목표 · 메시지)이 있어 누르면 그날 값을 불러옵니다.
- 오늘 것은 **학생이 한 명이라도 도전하면 바꿀 수 없습니다**(409, 같은 목표로 겨루게). 미리보기 계정 도전은 세지 않습니다.

### 자동으로 정하는 방식
- 설정이 없는 날은 서버가 날짜 문자열 해시(FNV-1a)로 **5.00 ~ 15.00초**(0.01초 단위)를 정합니다. 같은 날은 늘 같은 값입니다. 숨긴 값은 아니라서 선생님 화면에서 미리 보입니다.
- 숫자 보임은 3초, 메시지는 "오늘은 ○○초!"입니다.
- 학생 응답(홈 · 놀이터 · 시작)에는 **오늘 것만** 실립니다. 미래 날짜 설정 · 목표 · 메시지 필드는 없습니다. 시작할 때는 화면이 `mode: 'daily'`만 보내고, 목표는 서버가 정합니다.

### 보상
| 항목 | 값 | 근거 |
|---|---|---|
| 참여 보너스 | **8코인**, 하루 한 번 | 하루 코인 상한(150) **밖**이라 상한과 안 겹침. 하루 최대 +8로 경제 영향이 작음(보통 학생 하루 약 30코인의 1/4) |
| 등급 코인 | 기존 표(딱 맞춤 100 · 완벽 30 · 훌륭 15 · 좋음 8 · 아쉬움 4) | 기존 하루 150 상한 · 딱 맞춤 100코인 하루 한 번에 같이 셈. 챌린지로 상한이 늘지 않음 |
| 경험치 | 기존 표 | 그대로 |
| 보너스를 주는 판 | 눌러서 끝낸 판(너무 빠름 · 인터넷 느림 포함) | 하루 한 번이라 부정으로 더 얻을 것이 없음. 화면 가림(무효)은 없음 |

### 순위
- **오늘 순위**: 같은 학년대 · 그날 가장 작은 오차(서버가 믿은 판만). 미리보기 계정은 제외(자기 줄만), 비공개 학생은 "비공개 학생", 내 줄은 20등 밖이어도 보입니다. 기존 timing 순위 구조(`timingBoard`)와 같은 방식입니다.
- **어제의 챌린지 챔피언**: 순위 창 위에 어제 1 ~ 3등을 작게 보여 줍니다. 칭호는 이번에 만들지 않고 자리만 있습니다.
- 학생 화면: 순위 창에 "🎯 챌린지" 탭이 생기고, 챌린지 카드의 [오늘 순위] 버튼으로도 엽니다.
- 선생님 활동 기록: "10초 맞추기 오늘의 챌린지 7.77초 +0.03초 완벽".

### 저장 키
| 어디 | 키 | 크기 |
|---|---|---|
| 상태 | `state.timingDaily = { 'YYYY-MM-DD': { t, s, m, at, by } }` | 지난 14일 + 앞으로 13일까지(최대 27개, 4KB 이하) |
| 학생 | `p.timing.dc = { d, n, t, e, bn, pd, pe, pt }` | 오늘 챌린지(날짜 · 판 수 · 목표 · 최고 오차 · 보너스) + 지난 챌린지 하나 |
| 학생(고스트) | `p.timing.le` · `bse` · `db{d,e}` · `yb{d,e}` | 숫자 몇 개(240판 뒤 p.timing 전체 700바이트 이하) |

## 3. 고스트(내 기록 비교, V13.192)
- 결과 눈금자에 **옅은 점선 마커**를 그립니다. 하나는 어제(어제 가장 좋은 오차, 없으면 가장 최근 판) 위치, 다른 하나는 내 최고 기록 위치입니다(금색). 두 위치가 같으면 하나만 그립니다. 데이터가 없으면 아무것도 그리지 않습니다.
- 비교 한 줄: "어제보다 0.12초 가까워졌어요"(초록) · "어제와 똑같은 오차예요" · "어제보다 0.05초 멀어졌어요. 다시 해 봐요!". 0.01초 단위로 비교합니다. 새 기록이면 기존 NEW BEST 리본과 소리를 씁니다.
- 오늘의 챌린지: 지난 챌린지의 내 오차와 비교합니다. 어제 것이면 "어제 챌린지", 더 오래됐으면 "지난 챌린지"이고, 목표가 달라도 오차끼리 비교합니다.
- 서버가 믿지 못한 판(인터넷 느림)은 비교 줄을 쓰지 않고, 고스트 기록에도 넣지 않습니다.

## 검사
`server/timing-check.mjs`(멈춤 현상):
- 공개 연출 모든 프레임(60 · 30 · 20fps)에서 **눌린 시간보다 큰 숫자가 한 번도 나오지 않음**(보이는 숫자 = 멈춘 값)
- 누른 시각 규칙: 1초 안 이벤트 시각만 쓰고, 미래 · 다른 시계 · 값 없음이면 처리 시각
- 서버 측정과 다를 때: 숫자 · 오차 = 보낸 값, 코인 0, 순위 · 기록 제외, 경험치는 서버 측정, 활동 기록 문구
- 화면 코드: 누르면 프레임을 먼저 멈추고, 서버 응답으로 숫자를 바꾸지 않음

`server/timing-daily-check.mjs`(오늘의 챌린지 · 고스트):
- 설정 있는 날 / 없는 날 목표(자동은 날짜 시드 · 범위 · 0.01초 단위)
- 선생님만 설정(학생 403), 값 범위 · 날짜 범위, 오늘 것은 도전 뒤 잠김(409), 보관 14일
- 시작은 서버 목표, 하루 1판, 기본 판 수 · 기록과 따로
- 보상: 등급 코인 + 참여 보너스 8, 상한 150에 닿아도 보너스만, 보너스는 하루 한 번, 무효는 없음
- 순위: 미리보기 · 다른 학년 · 인터넷 느린 판 제외, 비공개, 내 줄, 어제 챔피언 1 ~ 3등
- 고스트 문구 경계값(0.01초 가까워짐 · 똑같음 · 멀어짐, 조사), 어제 · 지난 판 · 챌린지 고스트
- 저장 크기 상한(p.timing 700바이트, 설정 4KB), 학생 응답에 미래 날짜 설정 없음, 경로 권한, 활동 기록 한 줄

## 선생님이 정할 것(추천안 포함)
1. **챌린지 판 수**: 하루 1판(추천, 한 번에 거는 긴장감 · 공정) / 3판 중 최고.
2. **참여 보너스**: 8코인(추천) / 5코인 / 10코인.
3. **어제 챔피언 보상**: 지금은 자리만(추천: 한 주 써 본 뒤 칭호 "어제의 시계왕"을 따로 만들지 정하기).
