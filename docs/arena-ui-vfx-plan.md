## 1. 지금 화면 진단 — 왜 "AI 슬롭"으로 보이나

숫자는 `public/v13226~v13236.css`(아레나 CSS 10개)와 `public/modules/arena*.js`를 센 것이다.

| # | 문제 | 근거(화면 · 숫자) | 느낌 |
|---|---|---|---|
| 1 | **그라디언트 · 글로우가 아무 데나** | 아레나 CSS만 `radial-gradient` 151 · `linear-gradient` 151 · `conic` 21, 그림자(box/drop/text) 179개. 제목 글자(빨강 그라디언트 + 두꺼운 테두리), 버튼, 카드, 배지, 띠가 전부 빛난다 | 모든 게 "강조"라서 아무것도 강조되지 않음. 전형적인 생성형 UI 질감 |
| 2 | **색에 의미가 없다** | 아레나 CSS에 서로 다른 색 **302가지**. 친구 대전 모드 버튼이 초록 · 주황 · 파랑/빨강 반반, 연습장 띠는 빨강, 입구 띠는 빨강, 친구 대전 띠는 보라-파랑. 전투 버튼도 금 · 보라 · 주황 · 하늘 · 빨강이 섞여 속성과 무관 | 색을 보고 아무것도 알 수 없음 |
| 3 | **이모지 아이콘** | 아레나 JS에 이모지 **105개**(🎯5 🔒4 👑4 🔥4 💨4 ✨4 💥4 …). 규칙 설명 줄머리 🕹️🎯💨🔥, 연습장 허수아비 🎯🥊, 랭킹 🥇🥈🥉, 치명타 숫자 옆 💥, 입장권 🎟️ | 폰마다 그림체가 다르고 펫 그림(3D 페인팅)과 질감이 정반대 |
| 4 | **버튼 크기 · 모양 위계가 약하다** | 전투 버튼 6개가 모두 둥근 보석 공. 공격(약 86px)과 스킬(약 56px)의 차이는 있으나 회피 · 교체 · 필살기 · 스킬이 같은 모양 · 비슷한 크기 · 비슷한 채도. 버튼 아래 이름표가 잘림("되살아나는 …", "아홉 꼬리 둔갑") | 손이 먼저 가야 할 곳을 눈이 못 찾음 |
| 5 | **글이 너무 많고 화면에 흩어짐** | 입구에 규칙 4줄 + 조준 3카드 + 팀 슬롯(스킬 설명 4줄씩) + 기록 + 안내문 + 버튼 4개가 한 스크롤. 전투 중에도 스킬 이름 띠("운석 낙하" · "불 뿜기"), 안내 토스트("회피하면 피할 수 있어요!" · "필살기 게이지가 아직 다 안 찼어요"), "치명타!" · "효과가…" · "막음!"이 펫 머리 위에 **겹쳐서** 뜬다(diag-hit 왼쪽) | 읽을 게 많아 싸움이 안 보임 |
| 6 | **경기장에 비해 펫이 작고 정보가 위에 몰림** | 펫 그림이 약 70px(화면 폭의 18%), 체력 막대는 펫 위 약 60×5px로 숫자 없음. 위쪽 HUD는 "친구/나" 이름과 펫 얼굴 3개뿐이고 지금 싸우는 펫의 체력 · 필살기 게이지는 위에 없다. 타이머는 작은 알약. 경기장 가운데 절반이 빈 바닥 | 누가 이기고 있는지 한눈에 안 보임 |
| 7 | **그림체와 UI 질감이 따로 논다** | 펫 · 배경 · 배지 · 66번 효과 그림은 3D 페인팅(광택 · 부드러운 빛), 그 위 UI는 CSS 평면 알약 · 반투명 검은 상자 · 기본 고딕. 필살기 컷인은 화면 일부만 덮는 **검은 직사각형 + 주황 사선 띠**(diag-battle 2번째) | "다른 게임 위에 웹 페이지를 얹은" 느낌 |
| 8 | **효과가 CSS 도형** | 효과 조각은 `div` + 그라디언트(빔 · 할퀴기 · 지진 · 구슬). 불 구슬은 주황 원형 그라디언트 한 장(diag-hit 오른쪽), 66번 효과 그림(`fx-*.webp`)도 **256px 한 장짜리**(움직임은 CSS로 키우기/흐리기만) | 프레임이 바뀌는 "터짐"이 없어서 싸 보임 |
| 9 | **펫이 움직이지 않는다** | 공격 · 맞음은 표정 그림 한 장 바꾸기(`expressionSrc` attack · hurt) + 흔들기. 공격 준비 자세 · 반동 · 넉백 프레임이 없다 | 때리는 손맛이 없음 |
| 10 | **글꼴이 섞여 있다** | 제목은 주아(Jua), 본문은 Pretendard 계열, 숫자는 두 글꼴이 섞임(RP · 데미지 · 타이머). 테두리 굵기 · 둥근 정도도 제각각(`border-radius` 50% · 99px · 14 · 16 · 20 · 12 · 24 · 9 · 18px…) | 한 사람이 만든 게임처럼 안 보임 |

> 이미 있는 좋은 점(살린다): 히트스톱(`hitStop`) · 경기장 흔들기 · 맞은 쪽 카메라 줌 · 효과 조각 상한 · 저사양 자동 가벼운 연출 · 랭크 배지/배경 그림(69 · 65번)의 품질. **기법은 있는데 "대상이 작고, 효과 그림이 한 장이고, 글이 그 위를 덮어서" 안 보이는 것**이 핵심이다.

### 진단 상위 5개(요약)
1. 그라디언트 · 글로우 · 색 302가지 → 색에 의미 없음
2. 이모지 아이콘 105개 → 펫 그림체와 충돌
3. 버튼 위계 없음(같은 보석 공 6개, 이름표 잘림)
4. 글자 과잉 · 겹침(규칙 문단, 전투 중 토스트 · 스킬 띠 · "치명타!" 겹침)
5. 효과가 CSS 도형 + 한 장 그림, 펫 공격 자세 없음 → 손맛 · 퀄리티 부족

## 2. 참고 조사 — 가져올 "원칙"(그림 · 이름 · 로고는 가져오지 않음)

| 참고 | 화면 구성 원칙 | 우리 것으로 바꾸면 |
|---|---|---|
| 포켓몬 본편 배틀 메뉴 | 첫 화면은 **큰 선택지 4개**(싸운다/가방/포켓몬/도망)만. 기술 칸은 2×2, **칸 바탕색 = 기술 타입 색**, 남은 횟수(PP)를 작게. 정보창은 고를 때만 | 대기실 · 입구의 "할 일"을 3~4개 큰 카드로. 스킬 버튼 테두리/바탕 = **속성 색**. 스킬 설명은 길게 누를 때만 |
| 포켓몬 유나이트(실시간) | 스킬 버튼이 공격 버튼 둘레에 **부채꼴**, 쿨타임은 버튼 위 **숫자 + 어두운 덮개**. 궁극기는 시간 쿨이 아니라 **게이지가 차야** 켜짐(크고 따로). HUD는 최소, 정보는 화면 가장자리 | 공격 둘레 부채꼴 4칸(스킬①②·필살기·회피), 쿨 숫자, 필살기는 게이지 링이 차면 금빛 |
| 브롤스타즈 | 왼쪽 이동, 오른쪽 **큰 공격**, 그 아래/옆 **슈퍼(필살기)를 다른 색**으로, 톡=자동 조준 · 끌기=직접 조준. 결과 화면은 **승패 한 단어 + 캐릭터 포즈 + 보상 2줄** | 지금 조준 방식 유지(이미 비슷). 결과 화면을 "승리 + 내 펫 포즈 + 보상" 세 덩어리로 |
| 와일드리프트 · 모바일 MOBA | 엄지가 쉬는 자리에 주 공격, 자주 안 쓰는 것(귀환 · 상점)은 **엄지 사각지대**(왼쪽 아래 구석, 위 가장자리). 버튼이 클수록 오터치 감소 vs 화면 가림 → 크기 3단계 | 교체 · 이모트 · 나가기는 가장자리로 밀고 작게 |
| 클래시로얄 계열 | 아래 1/4은 손, 위 3/4은 전장. 내 정보 아래 · 상대 정보 위, **가운데 선 위에는 아무 글도 없음** | 상대 체력 위 · 내 체력 아래(엄지 위)로 나누고, 경기장 위 글자를 없앤다 |
| 격투 · 액션 손맛("Juice it or lose it" 등) | 한 번 맞을 때 **100ms 안에** 소리 · 히트스파크 · 흰 번쩍 · 짧은 히트스톱(2~3프레임) · 숫자가 겹친다. 흔들기는 **큰 것만**(다 흔들면 오히려 나빠짐) | 지금 기법을 등급(평타 · 스킬 · 치명 · 필살)별 표로 정리해서 "작은 건 작게, 큰 건 크게" |
| 플립북(시퀀스) 효과 | 효과 그림을 4~9칸 격자로 그려 순서대로 재생: **예비 동작 → 터짐(가장 밝은 1~2칸) → 흩어짐**. 같은 효과를 2~4가지로 그려 번갈아 쓰면 반복이 덜 티 남 | 66번 한 장 그림을 **6~8칸 시퀀스**로 다시 주문 |

가져올 원칙 8개(요약):
1. **첫 화면 큰 선택지 3~4개**, 설명은 길게 누를 때만(포켓몬 메뉴).
2. **색 = 의미**: 속성 색은 스킬 · 피해 숫자 · 효과에만, UI 뼈대는 무채색 + 금색 하나.
3. **엄지 영역 위계**: 공격 가장 크게 → 필살기 → 스킬 → 회피 → 교체 · 이모트(가장자리).
4. **필살기는 게이지 링**으로, 쿨타임은 **숫자 + 어두운 덮개**.
5. **내 정보 아래 · 상대 정보 위**, 경기장 위에는 펫 · 효과 · 피해 숫자만.
6. **타격 100ms 묶음**(소리 · 스파크 · 번쩍 · 히트스톱 · 숫자), 강도는 등급별로.
7. **플립북 효과**: 예비 → 터짐 → 흩어짐 6~8칸, 변형 2개.
8. **결과 화면 3덩어리**: 승패 한 단어 · 내 펫 포즈 · 보상.

## 3. 구성안

### A. UI 디자인 시스템

**A-1 배치(전투 화면, 390×844 기준)**

┌──────────────────────────────────┐
│ ‹      [상대]  ███████▒▒  1:47    │ ← 상대: 펫 얼굴 + 체력(숫자) + 남은 펫 ●●○, 가운데 타이머(크게)
│        ●●○   필살 ▰▰▱             │
│                                  │
│          (상대 펫 120px)          │ ← 펫 크기 70 → 110~120px, 경기장 가운데로

│      ── 경기장: 글자 없음 ──       │ ← 피해 숫자 · 효과만. 안내 토스트 금지
│                                  │
│           (내 펫 120px)           │
│                                  │
│ [나]  ████████▒  1,240 / 1,500   │ ← 내 체력 큰 막대 + 숫자(엄지 위)

│ [이모트]                         │

- 지금 버튼 아래 이름표(잘리는 것)를 없애고, **처음 3판만** 버튼 옆에 짧은 말풍선을 띄운다.

**A-2 정보 위계(무엇을 어디에)**

| 정보 | 지금 | 바꾼 뒤 |
|---|---|---|
| 지금 펫 체력 | 펫 머리 위 60px 막대, 숫자 없음 | **화면 위(상대) · 아래(나) 큰 막대 + 숫자**. 펫 머리 위에는 얇은 막대만 남김 |
| 필살기 게이지 | 버튼 안 | 필살기 버튼 링 + 내 체력 막대 밑 얇은 줄 |
| 쿨타임 | 버튼 원형 덮개 | 덮개 + 남은 초 숫자 |
| 타이머 | 작은 알약 | 위 가운데 크게(숫자 글꼴), 30초 남으면 빨강 |
| 남은 펫 | 위 띠 얼굴 3개 | 체력 막대 옆 ●●○ |
| 스킬 이름 | 펫 위 띠로 매번 | **필살기만** 컷인으로, 스킬은 이름 없이 효과로 |
| 치명타 · 막음 · 효과 굉장 | 글자가 겹쳐 뜸 | 숫자 모양으로 표현(치명 = 크고 금색 + 기울임, 막음 = 회색 작게), 글자는 한 번에 하나만 |

**A-3 색 규칙**
- **뼈대(카드 · 버튼 테두리 · 글자)**: 남색 계열 무채색 3단계(바탕 · 면 · 선) + **금색 하나**(강조, 화면당 1~2곳).
- **속성 색 8개만 의미**: 불 · 물 · 풀 · 땅 · 바람 · 얼음 · 독 · 별(펫 속성 규칙의 색과 같게). 스킬 버튼 테두리 · 피해 숫자 테두리 · 효과에만 쓴다.
- **팀 색 2개**: 우리 = 파랑, 상대 = 빨강(체력 막대 · 이름 · 발밑 링).
- 성공/보상 = 금, 위험 = 빨강(바닥 경고와 같은 빨강). 이 밖의 색(초록 · 주황 · 보라 그라디언트 버튼)은 없앤다.
- 그라디언트는 **그림 안에서만**(버튼 바탕 그림, 배지 그림). CSS 그라디언트는 체력 막대 같은 기능용 한두 개로 줄인다. 글로우는 "지금 누를 수 있음"(필살기 준비) 한 곳에만.

**A-4 글꼴**
- 한 가족: **제목 · 숫자 = 주아(이미 있음)**, 본문 = Pretendard 계열(이미 있음). 그 밖 없음.
- 숫자 전용 규칙: 체력 · 타이머 · 피해 · RP는 모두 주아 + `font-variant-numeric: tabular-nums`(자리 흔들림 없음) + 2px 진한 테두리.
- 크기 단계 5개만: 12 · 14 · 17 · 22 · 32px(제목), 피해 숫자는 24/32/44px 세 등급.
- 제목 글자의 빨강 그라디언트 + 두꺼운 테두리는 그림 로고 1장(입구 "펫 아레나")으로 바꾸고, 나머지 화면 제목은 흰 글자 + 그림자 하나.

**A-5 아이콘**
- **이모지 금지**(아레나 화면 105개 → 0). 이미 있는 숫자 · 글자로 충분한 곳은 아이콘을 지운다(규칙 설명 줄머리 등).
- 꼭 필요한 아이콘은 **한 시트 · 한 그림체**로 주문(C 참고): 조이스틱 · 공격 · 필살기 · 회피 · 교체 · 연습장 · 꾸미기 · 랭킹 · 입장권 · 코인 · 잠금 · 순위 1~3 메달 · 허수아비 3종.
- 스킬 아이콘은 속성 8개 × 모양 → 67-5~9(이미 주문서 있음)를 유지하되 **배경 없는 실루엣 + 속성 색 한 가지** 규칙으로.

**A-6 질감(펫 그림체와 맞추기)**

### B. 전투 연출 퀄리티

**B-1 지금 CSS 도형 효과의 한계**
- 모양이 "원 · 막대 · 사선"뿐이라 속성마다 색만 다르고 형태가 같다(불 구슬 = 주황 원, 독 구슬 = 보라 원).

**B-4 렉 예산(docs/performance-rules.md 8번 지킴)**
- 움직임은 transform · opacity만. 플립북은 **띠 그림 + `steps()` translateX**(배경 위치 · 너비를 움직이지 않음). 흰 실루엣은 미리 만든 그림(`filter` 금지).
- 효과 조각 상한 그대로(보통 40 · 저사양 20, 스킬당 8 · 4). 플립북 1개 = 조각 1개로 세어서 지금보다 조각 수가 줄어야 한다.
- 그림 용량: 효과 시퀀스 1장(8칸 × 192px 띠) **30KB 이하**, 전투 첫 로딩 추가 합계 **400KB 이하**(필요한 속성만 미리 받기, 나머지는 판 시작 VS 화면 동안).
- 디코드: 판 시작 VS 화면 동안 그 판 펫 속성의 효과만 `decode()`(지금 `warmArt` 방식).
- 지금 값(이 작업에서 잰 것, `node docs/arena-perf.mjs --cpu 4 --seconds 40`, 1:1): fps 59.5 · frame_p95 16.7ms · fight_max 66.6ms · fight_over50 1.6회/분 · input_p95 27.3ms · 효과 조각 최대 27개.
- 측정 목표(`node docs/arena-perf.mjs`, 폰 390px):
  - CPU 4×: frame_p95 ≤ 16.7ms 유지, fight_max ≤ 70ms, fight_over50_per_min ≤ 2, input_p95 ≤ 50ms, fx_max ≤ 지금(27).
  - CPU 6×: 저사양(ar-lite)이 자동으로 켜지고 fight_max ≤ 100ms.
  - 2:2(`--mode 2v2`)에서도 같은 기준.
- 서버 · 데이터는 바뀌지 않는다(그림 · CSS · 화면 코드만). 새 데이터 묶음 없음, `check:load` 영향 없음.

### C. 그림 · 소리 제작 방식

**C-1 지금 그림 GPT 방식의 한계**
- 주문서마다 "65 · 66번 그림을 열어 맞추라"고 하지만, 시트마다 따로 생성해서 **테두리 굵기 · 빛 방향 · 채도 · 선 두께**가 조금씩 다르다(65 · 66 · 69가 이미 미세하게 다름).
- 한 장짜리 그림은 잘 나오지만 **같은 효과의 여러 칸(시퀀스)** 은 칸마다 모양이 튀기 쉽다.
- 67(버튼 9장)은 "광택 보석 + 금 테두리"를 **모든 버튼에 똑같이** 요구해서, 그려도 지금 진단 4번(위계 없음) · 1번(아무 데나 광택)이 그림으로 굳어진다.

**C-2 대책**
1. **스타일 가이드 한 장 먼저(70번)**: 한 시트 안에 금 테두리 굵기 3단계 · 남색 유리 판 · 속성 색 8칸(색 칩) · 아이콘 그림체 예시 3개 · 빛 방향(왼쪽 위) · 선 굵기를 그린다. 이후 모든 주문서는 "**70-1 스타일 가이드와 65-2를 열어**" 맞추라고 쓴다(기존 Drive 그림 열기 규칙 유지).
2. **효과 시퀀스 주문 방식**: 한 장 = 가로 띠 8칸(각 256×256, 2048×256) 또는 4×2 격자. 프롬프트에 칸별 할 일을 적는다(1~2 모임 · 3 번쩍 · 4~5 터짐 최대 · 6~8 흩어짐), **가운데 기준점 고정 · 칸 사이 크기 변화 30% 이내**. 받은 뒤 `fit-sheets.mjs`처럼 잘라 띠로 붙이는 빌드 스크립트를 만든다.
3. **아이콘 세트는 한 번에**: UI 아이콘 16개를 4×4 한 시트로(같은 생성 = 같은 그림체). 이모지 105개를 대신한다.
4. **67 주문서 고치기(추천)**: 지금 9장 → 6장으로 줄이고 위계를 넣는다.
   - 67-1 공격(가장 화려, 속성 보석은 8색 대신 **무채색 보석 + CSS로 속성 색 테두리**) · 필살기(게이지 링 자리 비움) · 회피 · 교체는 **은 테두리 · 무광**으로 한 단계 낮게.
   - 67-2 쿨 덮개 · 누름 · 준비됨은 유지.
   - 67-3 조이스틱은 유지, 이모트 바탕은 무채색으로.
   - 67-4~9 아이콘은 "광택 3D" 대신 **"흰 실루엣 + 얇은 속성 색 테두리"**(작게 봐도 읽히고 버튼과 안 싸움)로 바꾸고 3장으로 합친다.
5. **주문서 규칙 두 가지 유지**: 모든 주문에 ① Drive의 기존 그림(65-2 · 65-5 · 66 · 69 + 새 70-1)을 열어 그림체를 맞추라는 말, ② 정해진 Drive 폴더 "SUMUS 펫 아레나 NN (Runner용)"에 정확한 파일 이름 "NN-k.png"로 저장하라는 말.

- 1~3은 그림 없이 바로 할 수 있어 **선생님이 가장 빨리 차이를 느끼는 순서**다. 5(주문)는 1과 동시에 내보내면 6 차례에 그림이 와 있다.
- 각 PR에 "렉 방지 점검" 칸(8번 규칙 · arena-perf 숫자 · check:load p95) 포함, 바뀐 규칙은 `server/*-check.mjs`(예: 아레나 화면 이모지 0개 · 아레나 CSS 색 토큰 밖 색 상한)에 검사로 남긴다.
- 기능(전투 규칙 · 보상 · 서버)은 건드리지 않는다.

### E. 선생님이 정할 것(질문마다 추천안)

1. **방향: 지금 "광택 보석 · 금" 느낌을 유지하며 정리할까, 더 단순한(무채색 + 금 한 가지) 쪽으로 갈까?**
   → 추천: **정리형** — 펫 · 배경 그림이 광택 3D라 그 질감은 유지하되, 광택은 버튼 그림 · 배지에만, 나머지는 무채색 유리 판.
2. **전투 버튼 배치: 지금처럼 공격 + 둘레(부채꼴)로 갈까, 브롤 식으로 공격 · 필살기 2개만 크게 + 스킬 작게 갈까?**
   → 추천: **부채꼴**(스킬 2개 + 필살 + 회피를 엄지 한 번에). 크기 위계로 공격이 가장 크게.
3. **펫 크기를 70 → 110~120px로 키워도 될까?**(경기장이 좁아 보일 수 있음. 판정 범위는 그대로, 보이는 것만)
   → 추천: **110px**부터, 2:2 · 난투는 95px.
4. **전투 중 글자(스킬 이름 띠 · 안내 토스트 · "치명타!")를 거의 없애도 될까?**
   → 추천: **필살기 이름만 컷인으로**, 안내는 처음 3판만 버튼 옆 말풍선.
5. **67 주문서(버튼 9장)를 이 구성안대로 고쳐 다시 낼까?**
   → 추천: **고친다**(9 → 6장, 위계 · 무채색 아이콘). 그리기 전이라 비용 없음.
6. **스타일 가이드(70-1)를 먼저 받고 나머지 그림을 주문할까?**
   → 추천: **예**(한 장 먼저 → 선생님 확인 → 나머지).
7. **펫 개별 공격 자세 그림(펫 수 × 3장)까지 할까?**
   → 추천: **아니오**, 공용 자세 변형(기울이기 · 늘이기 · 잔상)으로. 나중에 인기 펫 몇 마리만 추가 검토.
8. **시작 순서: 1~3단계(그림 없이 정리 · HUD · 손맛)부터 해도 될까?**
   → 추천: **예**, 1단계와 동시에 70 · 67(수정) 주문서를 낸다.
