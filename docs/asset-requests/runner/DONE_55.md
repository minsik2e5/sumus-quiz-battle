# 그림 55 완료 기록

공룡 펫 6종의 시트 36장을 Codex 내장 이미지 생성 기능으로 한 장씩 만들고, 지정된 분할 도구로 WebP 168개를 추가했다. Google Drive, 외부 유료 API, API 키, 운영 Supabase는 사용하지 않았다.

- 위치: `public/assets/pets/`. 파일명은 `slice-map.csv`의 55a/55b/55c 항목과 일치한다.
- 기본 그림: `<key>-0.webp`부터 `<key>-3.webp`, 작은 그림: `<key>-<단계>-s.webp`.
- 표정: 단계 1~3의 `happy`, `eat`, `sad`, `cheer`. 알 반응: 단계 0의 `happy`, `eat`. 전투: 단계 1~3의 `attack`, `hurt`.
- 합본 검토 이미지: `public/assets/previews/runner-55.webp`. 36개 분할 미리보기를 합쳤다. 표정·전투 미리보기의 첫 그림은 크기 비교용 기본 그림이다.
- 원본 시트 PNG는 작업용 디렉터리에만 보관하고 커밋하지 않았다. 생성 도구가 반환한 큰 정사각형 이미지는 1024×1024 투명 PNG로 정규화한 뒤 분할했다.

## 프롬프트와 참고 그림

`split/55a-*.txt`, `split/55b-*.txt`, `split/55c-*.txt`를 사용했다. `STYLE REFERENCE`, `CHARACTER REFERENCE`, `Also open`, `WHEN DONE`으로 시작하는 줄을 제거하고, CODEX_PROMPT_55.md의 첨부 참고 문장을 세 번째 줄에 넣었다. 설정 시트에는 기존 panda/calf/polarbear 그림(렉스에는 haechi도 포함), 이후 시트에는 새로 만든 해당 단계 그림을 첨부했다. 전투 최초 생성에는 elephant-2-attack/hurt도 포즈 참고로 첨부했다. 수정 생성에는 해당 후보와 캐릭터/포즈 참고를 첨부했다. 투명 여백, 소품 유지, 이빨 없는 친근한 입 모양을 강조했고, 위 표의 오류는 해당 칸만 수정하도록 추가 지시했다.

## 검수

- 168개 최종 WebP의 파일명·누락·비어 있지 않음·크기 검사를 통과했다.
- 모든 최종 WebP의 네 모서리 alpha는 정확히 0이다. 작은 그림은 160×160, 나머지는 512×512다.
- 지정 도구의 투명 배경·비어 있는 칸 검사를 통과했다. 흰 상자나 체크무늬 배경을 넣지 않았다.
- 생성 시트와 합본을 눈으로 확인했다. 알의 무얼굴, 단계 구분, 기본 색·소품, 무섭지 않은 표현, 공격·맞음 방향을 확인하고 위 표의 후보를 수정했다.
- **눈으로 확인 필요:** 합본은 PR 검토용이다. 최종 미술 취향과 실제 앱에서의 크기·포즈 전환은 코드 등록 이후 선생님의 최종 확인이 필요하다.
- 기존 그림 파일 수정·삭제는 없다. PR 기준 브랜치 대비 `public/assets/` 변경은 새 파일 추가뿐이다.
- 운영 브랜치 대비 직접 비교하면 주문서 브랜치에 이미 존재하던 SFX MP3 14개의 부재가 표시된다. 해당 차이는 작업 전 기준 브랜치에도 동일하며 이 PR에서 삭제한 파일이 아니다. 이미지 수정·삭제는 없다.

## 빌드와 검사

- `npm ci`: 성공. 분할 도구용 sharp는 `--no-save --package-lock=false`로 설치했다. package.json·lockfile은 변경하지 않았다.
- `npm run build:assets`: 성공. content-validation PASS, browser-syntax PASS. 허용된 `pet-art.js`, `sw.js`만 결과에 포함한다.
- `npm run check:cloudflare`: 성공(종료 코드 0). Supabase 관련 로그는 검사 내부의 가짜 fetch 응답에서 발생했으며 운영 연결은 없다.
- `npm run check`: 실패. 다음 메시지를 그대로 기록한다.

```text
Error: [release-check] FAIL · V13.99 battle.js sends idx with choice and spelling answers and locks the word once sent
```

`server/battle-check.mjs:325`의 문자열 비교가 LF 줄바꿈을 요구하며 이 Windows 체크아웃의 core.autocrlf는 true다. 관련 `public/modules/battle.js`와 검사 파일은 기준 브랜치와 동일하다. 지침대로 앱 코드·검사 파일을 고치지 않았다. 이 실패 이후의 release-check 항목은 실행되지 않았으므로 전체 PASS로 간주하지 않는다.

추가 검증: 커밋 예정 내용을 Git 인덱스에서 LF 줄바꿈으로 꺼낸 별도 검증 폴더에서 빌드를 실행한 뒤 같은 `npm run check`를 실행했다. **[release-check] PASS 3107/3107**을 확인했다. 앱 코드·검사 파일 수정 없이 줄바꿈 차이가 원인임을 확인했다. 최종 `sw.js`는 이 LF 검증 빌드의 산출물을 사용한다. 최초 Windows 실패 메시지도 위에 보존했다.
