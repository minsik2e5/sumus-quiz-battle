# 그림 주문서 39 · 40 · 41 작성 기록 (몬스터 레벨 2.0 그림 먼저)

구성안 `docs/monster-level-design.md`의 추천안을 선생님이 승인해서, 새 몬스터 18종과 지역 배경의 **주문서만** 만들었다. 그림은 아직 없다(Codex에 넘긴다). 앱 코드 · 규칙 · 버전은 바꾸지 않았다(문서라 버전을 올리지 않는다).

- 시트 하나 = 프롬프트 하나(`split/39a-1 …` ~ `41-4 …`). 몬스터 시트는 35번과 똑같이 2×2(기본 · 공격 · 맞음 · 쓰러짐), 투명 PNG, 글자 · 숫자 · 로고 없음, 기존 몬스터(10 · 12 · 22 · 35)와 같은 그림체. 시트마다 "기존 몬스터와 헷갈리지 않게 보이는 포인트" 문장이 들어 있다.
- `slice-map.csv`에 `prompt_no` **651 ~ 672**를 더했다(몬스터 651 ~ 668, 배경 669 ~ 672). 기존 마지막 번호는 650(38e)이었고 36 · 37 · 38(펫)과 겹치지 않는다. 39 · 40 · 41은 주문서 번호이고 slice-map의 `prompt_no`(일련번호)와는 다른 번호다.
- 생성기: `docs/asset-requests/runner/build-39.mjs` (몬스터 생김새 · 포인트 문장 · 지역 배경 장면 · Codex 지시문을 여기서 만든다. 다시 돌려도 같은 결과다. `build-runner.mjs`는 돌리지 않는다).
- **Codex 지시문 3개는 처음부터 Drive 없이** 저장소 안의 그림(`public/assets/monsters/*.webp` 등)을 참고 그림으로 붙이는 방법을 담았다(36 · 37 · 38과 같은 "프롬프트 손보기"). 시트 프롬프트(`split/`)에는 Drive 문구를 그대로 두었다(선생님이 그림 GPT에 Drive로 보낼 때 쓴다).
- 결과 시트는 `/tmp/art/<시트 번호>.png`로 저장하고 `fit-assets.mjs`(몬스터, `--stand-same`)로 잘라 `public/assets/monsters/`에 넣는다. 배경은 720×1080 webp(150KB 이하)로 줄여 `public/assets/monster-stage/`에 넣는다.

## 확인한 것 (직접 돌려 봄)
- 이 그림만으로는 새 몬스터가 지도(몬스터 사냥)나 몬스터전 레벨에 나오지 않는다. 새 key는 `MONSTERS` · `HUNT_MONSTERS`에 없어서 어디에서도 쓰이지 않는다. 레벨 순서 등록은 구성안 §7의 세션 2에서 코드로 한다.
- `build:assets`는 그림 폴더에서 기본 · 공격 · 맞음이 다 있는 key를 모아 `monster-art.js`(`MONSTER_ART`)를 만들 뿐이다. 그림이 먼저 들어와도 앱이 깨지지 않는지 가짜 그림(기존 `mochi` 4장을 `bookmarkbat` · `yearendlord` 이름으로 복사)을 넣어서 확인했다: `npm ci` 뒤 `npm run build:assets`(`monster-art` 34 → 36종), `npm run check`(**PASS 2290/2290**), `npm run check:cloudflare`(통과) 모두 정상이었다. 가짜 그림은 지우고 `build:assets`를 다시 돌려 34종으로 되돌렸다(저장소에 남은 변경 없음).
- 지역 배경 폴더 `monster-stage/`는 새 폴더다. 그림이 들어온 뒤 Codex가 `build:assets` · `check` · `check:cloudflare`를 한 번 더 돌린다(지시문 3번).
