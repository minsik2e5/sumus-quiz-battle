## 0. 렉 원인 측정

### 어떻게 쟀나
- 새 도구 `node docs/arena-perf.mjs --cpu 4|6`(야차전 `docs/yacha-perf.mjs`와 같은 방식).
- 진짜 아레나 화면(`public/modules/arena.js`)을 폰처럼 연다: 세로 390×844, 배율 3, 터치, CPU 4배 · 6배 느리게.
- 탭이 스스로 조종한다: 방향을 바꾸며 움직이고, 공격은 계속 누르고, 스킬 1 · 2 · 필살기 · 회피를 틈틈이 누른다.
- 팀: 신화(구미호) · 전설(불새) · 일반(곰) 대 용 · 거북 · 강아지. 빔 · 구슬 · 지진 · 돌진 · 필살기가 다 나온다.
- 한 번에 약 85~90초. 두 번 잰 값이다.
- `--tags`를 붙이면 "긴 프레임에 무엇이 같이 생겼나"를 센다. 무거운 곳 순위는 이것으로 정했다.

## 1. 실시간 친구 대전 (1:1 · 1:1:1 · 2:2)

### 1-1. 판 종류

> ✅ **1:1:1 난투 · 2:2 팀전은 v13.232.0에서 만듦**(CHANGES_v13.232.0.md). 같은 `ArenaRoom` · 롤백을 여러 명으로 넓혔다. 빈자리 컴퓨터는 보상 계산에서 빠지고, 다른 사람끼리 때릴 때는 화면 멈춤(히트스톱)을 빼서 느린 폰 렉을 줄였다.

| 판 | 사람 | 각자 펫 | 이기는 법 | 시간 |
|---|---|---|---|---|
| ⭐ **1:1** | 2명 | 3마리(지금처럼 교체) | 상대 3마리를 다 쓰러뜨리기 | 2분 |
| **1:1:1 난투** | 3명 | ⭐ 2마리 | 마지막까지 남기. 시간이 다 되면 쓰러뜨린 수 → 남은 체력 | 2분 |
| **2:2 팀전** | 4명 | ⭐ 2마리 | 상대 팀 4마리를 다 쓰러뜨리기 | 2분 30초 |

- 1:1:1 · 2:2에서 각자 2마리인 이유: 펫이 6~8마리면 판이 너무 길고, 화면에 펫이 4마리 넘게 있으면 느린 폰이 무거워진다.
- 경기장에는 **한 사람당 한 마리만** 나와 있다(지금 규칙과 같다). 그래서 화면에 펫은 최대 4마리.
- 2:2는 팀 친구를 못 때린다. 팀 친구 스킬(보호막 · 회복)은 팀 친구에게도 걸린다.
- 1:1:1은 "가장 약한 사람 몰아치기"를 막으려고, 쓰러뜨린 사람에게만 점수를 준다(막타 점수).

### 1-3. 구조: 어떻게 실시간으로 맞추나

지금 전투는 **씨앗 + 조작 기록(몇 번째 틱에 무엇을 눌렀나)만으로 정해진다**(`public/modules/arena-rules.js`, 무작위 · 삼각함수 없음). 이걸 살릴 수 있다.

| | A. 입력만 주고받기 + 롤백 ⭐ | B. 입력 지연 lockstep | C. 서버가 판정(서버가 전투를 돌림) |
|---|---|---|---|
| 어떻게 | 각 폰이 같은 전투를 돌린다. 내 조작은 바로 보이고, 친구 조작은 "방금 하던 대로"라고 짐작해 돌리다가, 진짜 조작이 오면 그 틱으로 **되감아 다시 계산** | 모두의 조작이 다 모일 때까지 틱을 기다린다 | 방 객체가 20틱/초로 돌리고 위치를 뿌린다 |
| 내 조작감 | **바로 반응**(지금과 같다) | 버튼 뒤 0.15~0.3초 늦게 움직임 → 답답 | 0.15~0.3초 늦음(예측을 넣으면 복잡) |
| 친구 펫 | 가끔 살짝 "순간 보정"(되감을 때) | 부드럽지만 늦음 | 부드럽지만 늦음 |
| 서버 일 | 조작 순서만 정해 되돌려 줌(가볍다) | 같다 | 전투 계산 + 위치 20번/초 보내기(무겁다) |
| 지금 코드 재사용 | **전투 파일 그대로**, 되감기용 저장 · 불러오기만 추가 | 그대로 | 전투 파일을 서버 틱에 붙여야 함 |
| 속임수 | 조작만 보내므로 체력 · 피해를 고칠 수 없다. 끝나면 서버가 다시 돌림 | 같다 | 가장 안전 |

- ⭐ **추천: A(롤백)**. 이유:
  - 아레나는 "누르면 바로 피하기"가 재미의 핵심이다. B · C는 폰 지연(150~300ms) 때문에 회피가 늦게 느껴진다.
  - 되감기가 싸다. 잰 값: 한 틱 계산 **1.4µs**(이 컴퓨터), 상태 복사 36µs(4KB). 느린 폰이 10배 느려도 0.3초(6틱) 되감기는 **0.5ms 안**이다.
  - 2분 판 서버 확인은 지금처럼 `runArena`로 다시 돌리면 된다.

#### 방 객체 `ArenaRoom`(새 Durable Object, BattleRoom · PartyRoom과 같은 모양)
- 판 하나에 방 하나. 폰은 WebSocket으로 들어온다. **메인 상태 객체는 시작 · 끝에만 한 번씩**(규칙 6).
- 방이 하는 일
  1. 조작을 받으면 **틱 번호를 확인**(너무 옛날 · 너무 미래면 고쳐서 받음)하고 순서를 정한다.
  2. 0.1초마다 한 번, 모은 조작을 모두에게 보낸다("이 틱까지 확정").
  3. 끝나면 확정된 모든 조작으로 `runArena`를 돌려 승패를 정하고 메인 객체에 결과를 한 번 보고한다(화면이 보낸 승패는 믿지 않는다 — 지금과 같다).
- 저장: 조작마다 저장하지 않는다. PartyRoom처럼 메모리에 두고 **5초마다 한 번** 저장(판 하나 ≈ 30줄).

#### 틱 · 메시지 예산

| 항목 | 값 |
|---|---|
| 전투 틱 | 50ms(지금과 같다, 20틱/초) |
| 폰 → 방 | 바뀐 조작만, **0.1초에 최대 1번** 묶어 보냄. 보통 초당 3~5번 |
| 방 → 폰 | 0.1초에 1번(확정 조작 묶음) + 1초에 1번 확인(상태 요약 해시) |
| 메시지 크기 | 조작 1개 ≈ 6바이트. 묶음 하나 200바이트 아래. 512바이트 넘으면 버림 |
| 1:1 판 하나(2분) | 들어오는 메시지 약 1,000개 → Cloudflare 계산으로 요청 약 50건(웹소켓 20개 = 1건) |
| 하루 200판(2:2 포함) | 요청 약 2만 건 → 무료 한도 10만 건의 20%. 쓰기 약 6,000줄 → 하루 10만 줄의 6% |

- 하루 판 수 상한(코인 판): 지금 혼자 판과 합쳐 **하루 5판**. 연습 판은 횟수 제한 대신 "방 만들기 1분에 1번".

| 지연 150~300ms | 롤백으로 내 펫은 바로 반응. 친구 펫은 최대 8틱(0.4초)까지 되감는다. 그보다 늦은 조작은 "늦게 누른 것"으로 받는다. |
| 지연이 계속 400ms 넘음 | 화면 위 신호 막대가 빨간색. 그 사람 조작은 0.1초 늦춰 받아 되감기를 줄인다. |
| 끊김 3초 | **컴퓨터가 대신 조종**(지금 컴퓨터 상대 AI, 보통 솜씨). 방이 "틱 N부터 컴퓨터" 조작을 넣어서 모든 폰이 같은 결과. |
| 다시 들어옴 | 방이 씨앗 + 확정 조작을 다시 주면 폰이 빠르게 다시 계산(2분 판 2,400틱 ≈ 느린 폰 40ms)하고 이어서 조종. |
| 끝까지 안 들어옴 | 판은 끝까지 간다. 그 사람은 패배 · 보상 없음(1:1:1 · 2:2에서 남은 사람들은 정상 보상). |
| 상태가 어긋남(버그) | 1초마다 상태 해시를 비교. 다르면 방이 그 폰에 확정 조작을 다시 보내 다시 계산. 끝 판정은 늘 방. |

#### 보상 · 코인 농사 막기
- 승패와 보상은 **방이 다시 돌린 결과**로만 정한다.
- ⭐ **같은 친구끼리**: 같은 상대(2:2는 같은 4명 조합)와 코인 판은 **하루 2판까지**. 그 뒤는 연습 판(기록만).
- 한쪽이 거의 조작하지 않으면(조작 20개 미만 · 준 피해 0) 그 판은 **둘 다 보상 없음**(져 주기 막기).
- 친구 대전 보상은 혼자 판과 같은 크기(이기면 12코인, 쓰러뜨림 있으면 져도 4코인). 입장권도 같이 쓴다. **새 재화 없음.**
- 컴퓨터가 채운 자리 · 끊겨서 컴퓨터가 조종한 시간이 절반 넘는 사람은 보상 없음.

## 2. 조준 직접 조작

지금: 공격 · 스킬이 **늘 상대를 자동으로 향한다**(`aimAt(s, other(s))`). 그래서 움직임이 공격과 상관없다.

| 방법 | 어떻게 | 장점 | 단점 |
|---|---|---|---|
| ⭐ **A. 움직이는 방향 = 바라보는 방향** + 약한 보정 | 조이스틱으로 움직이는 쪽을 바라보고, 기본 공격은 그쪽으로. 바라보는 쪽 ±25° 안에 상대가 있으면 살짝 끌어당긴다 | 손가락 2개로 충분. 폰에서 가장 편하다 | 뒤로 빠지면서 쏘기는 못 함 |
| B. 오른쪽 조준 스틱 | 화면 오른쪽에 두 번째 스틱 | 쏘면서 도망 가능 | 버튼 6개 + 스틱 2개 → 초등 · 중학생 폰에 너무 복잡 |
| ⭐ **C. 스킬 버튼 끌어서 조준** | 스킬 · 필살기 버튼을 누른 채 끌면 경기장에 화살표 · 부채꼴 · 원이 보이고, 놓으면 그 방향으로. **그냥 톡 누르면** 바라보는 방향(보정 포함) | 정확한 스킬 조준 = 실력. 톡 누르기도 되니 쉽다 | 버튼 반응 코드가 조금 늘어남 |

- ⭐ **추천: A + C를 같이.**
  - 기본 공격: 바라보는 방향, 보정 ±25°(쉬움 모드 ±40°).
  - 스킬 · 필살기: 톡 = 바라보는 방향, 끌기 = 내가 고른 방향.
  - 서 있으면 마지막으로 바라본 방향을 유지.
  - 설정에 "자동 조준(지금 방식)" 켜기를 남겨 둔다(처음 하는 학생 · 저학년용).
- 규칙 파일: 조작 코드에 방향 칸 추가(예: `[틱, 코드, 방향 0~15]`, 16방향). 삼각함수 없이 미리 정한 표로 계산(지금 8방향 표와 같은 방식).
- 컴퓨터 상대도 같은 규칙(조준 정확도 = 솜씨). 승률은 봇 시뮬로 다시 맞춘다(쉬움 ≈ 90% · 보통 ≈ 50% · 어려움 ≈ 35%).

### 등급 세기 규칙을 아레나에서도

규칙: **기본 ≈ 영웅 < 전설(+약 6%) < 신화(+약 6%), 한정 ≈ 기본.**

- ⚠️ **지금 아레나는 이 규칙과 다르다**(`arena-rules.js` `RANK_MUL = [1, 1.06, 1.1, 1.14]`).

  | 등급 | 지금 능력치 | 규칙에 맞는 값(제안) |
  |---|---|---|
  | 일반(기본) | ×1.00 | ×1.00 |
  | 영웅 | ×1.06 | **×1.00** |
  | 전설 · 시리즈 | ×1.10 | **×1.06** |
  | 한정 | ×1.10 | **×1.00** |
  | 신화 | ×1.14 | **×1.12** |

  → ①단계 PR에서 같이 고치길 추천한다(질문 Q7).
- 능력치 배수는 시작점일 뿐이다. 진짜 기준은 **승률**이다.
  - 새 도구 `node server/arena-sim.mjs tiers 300`: 같은 단계 · 같은 레벨 펫 쌍마다 300판, 양쪽 모두 검사용 봇(같은 솜씨)이 조종.
  - 목표: 일반 대 영웅 50% ± 3, 전설 대 일반 ≈ 55%, 신화 대 전설 ≈ 55%, 한정 대 일반 50% ± 3.
  - 스킬트리 가지마다(A/B) 승률 차이 ±3% 안 → 어느 쪽을 골라도 손해가 없게.
  - `server/arena-check.mjs`에 빠른 판 수로 같은 범위를 확인하는 검사를 넣는다.
