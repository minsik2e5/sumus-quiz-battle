# 게임 렉 점검 보고서 (2026-11, v13.246.0)

## 쉬운 요약
- **보통 폰(1×)에서는 모든 게임이 60fps 가까이 나오고 끊김이 없습니다.**
- 느린 폰(4× · 6×로 흉내)에서 끊김이 보이는 게임은 **낚시 · 인형뽑기 · 펫 대행진 · 펫 아레나**입니다.
- 이번에 **낚시를 고쳤습니다**(느린 폰에서 끊김이 절반 이하로). 짝 맞추기는 시계를 가볍게 해 계산 시간이 약 35% 줄었습니다.
- 아레나 · 짝 맞추기의 다른 수정 두 가지는 재 보니 좋아지지 않아 **되돌렸습니다**.
- 판을 5번 이어 해도 메모리가 계속 늘지는 않는지, 게임을 나간 뒤에도 도는 것이 있는지 확인했습니다(아래 5장).
- 남은 것(대행진 · 아레나 · 인형뽑기)은 원인과 고칠 방법만 적었습니다. 다음 작업에서 하나씩 고칩니다.

판정 기준(조건마다 3번 잰 중간값): **좋음** = 50ms 넘는 프레임이 분당 2번 이하 · **주의** = 분당 2~20번 · **렉** = 분당 20번 넘음 또는 fps 45 미만.
측정: 세로 폰 390×844 · 배율 3 · 터치, CPU 1× · 4×(품질 자동) · 6×(대행진 · 아레나는 최저 품질 고정). 이 컨테이너는 화면을 CPU로 그려서 실제 폰보다 칠하기가 느립니다. **숫자는 같은 기계에서 잰 전 · 후끼리만 비교합니다**(예전 문서 숫자와 직접 비교하지 않음).
원본: `docs/game-lag-data/*.jsonl`, 집계 `node docs/game-lag-data/scripts/{sum,gsum,asum}.mjs <파일>`.

## 2. 원인
확인된 것(측정 · 트레이스 근거, `docs/game-lag-data/trace-*.txt`):
1. **낚시**: 낚싯대 SVG 요소 40~50개를 매 프레임 innerHTML로 새로 만들었습니다(`drawRig`). 30초에 배치 무효화 1139번, HTML 해석 1.4초.
2. **짝 맞추기**: 시계 글자를 매 프레임 찾고 써서 배치가 프레임마다 다시 됐습니다. 50ms 넘는 프레임 자체는 카드를 맞힌 순간(43~59ms)과 라운드가 바뀔 때입니다.
3. **인형뽑기**: 집게 위치를 left · top · width(%)로 매 프레임 써서 배치(`drawClaw`), 판 중 그림 디코드 274ms/18초.
4. **펫 아레나**: 판 시작(입장 꾸미기 330~550ms), 품질 단계가 내려가는 순간(약 117ms), 2:2 · 난투는 펫 3~4마리 그리기 자체가 4×에서 프레임을 넘깁니다.
5. **펫 대행진**: 칠하는 넓이(위 설명). 판 시작 전 그림 굽기 0.9~1.3초 멈춤(카운트다운 전이라 플레이에는 영향 없음).
6. **10초 맞추기 · 가위바위보 · 야바위**: 결과 · 배너가 뜨는 순간 한 번.

## 5. 5판 연속 · 나간 뒤
CPU 1×, 판을 5번 이어서 하고 판마다 가비지 수거 뒤 잰 값입니다(`docs/game-perf.mjs --game runner --rounds 5`, `docs/arena-perf.mjs --rounds 5`).

| 게임 | 판마다 fps | JS 힙(MB) | DOM 노드(문서 밖 포함) | 나간 뒤 3초 |
|---|---|---|---|---|
| 펫 대행진(스테이지 1) | 59.9~60, 50ms↑ 0 | 5.5 → 5.8 → 5.9 → 6.0 → 6.1 | 1208 → 2379 | rAF 0회/초, 새 타이머 없음(앱의 초대 · 데이터 확인 폴링 2개만), 소리 0 |
| 펫 아레나 혼자 판 | 59.9~60, 50ms↑ 0~1 | 4.6 → 5.0 → 5.2 → 5.4 → 5.5 | 374 → 1085 | rAF 0회/초, 새 setInterval 0 |

- **판이 거듭돼도 프레임은 떨어지지 않습니다.** 나간 뒤 도는 rAF · 타이머도 없어서 고칠 것이 없었습니다.
- 힙은 판마다 0.1~0.4MB씩 조금 늘고, 노드 수도 판마다 대행진 약 290개 · 아레나 약 170개씩 늡니다. 대행진은 판마다 문서 안 요소 수가 168~184개로 같았습니다(`--dom`). 그래서 늘어나는 노드는 화면에 쌓이는 것이 아니라 **떼어 낸 요소를 JS가 아직 붙잡고 있는 것**으로 봅니다.
- 판정: **주의(급하지 않음)**. 이 속도면 쉬는 시간에 20판을 해도 힙이 몇 MB 늘어나는 정도라 폰에서 느려질 수준은 아닙니다. 다음 점검 때 힙 스냅샷으로 무엇이 붙잡고 있는지 찾습니다.

야차전 봇 대결: 앞 세션에서 대결 중 홈 탭을 강제로 누르자 rAF와 100ms 타이머(`battle-bot.js`)가 계속 돌았습니다. 코드를 보니 대결이 시작되면 `goFull()`이 #app 전체를 바꿔 **아래 탭이 화면에 없습니다**. 나가는 길(`leaveScreen` → `closeSocket` → `B.local.close()`)은 타이머를 모두 끕니다. 그래서 실제 화면에서는 생기지 않는 경로로 보고, 고치지 않았습니다.
