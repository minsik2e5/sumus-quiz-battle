## 0-1. ①단계에서 선생님이 정한 것(v13.241.0, `CHANGES_v13.241.0.md`)

- 구출 펫 = 내 펫 중 판마다 무작위(서버 판 씨앗). 난도 목표는 `runner-rules.js` `stageTarget`(보스 15%p 낮게 · 다음 스테이지 쉬어 가기), 3연패마다 응원 정령 +10%(최대 30%).

- 아래 2장 숫자 중 ①에서 바뀐 것: 사격 기본 피해 0.6 → 1, 바위 HP = 기대 무리 × k, 부딪힘 폭 0.45R, 스테이지마다 "위험 세기"(바위 · 나쁜 문 · 톱날 · 망치에 곱함)를 봇으로 맞춤.

## 0. 선생님이 정한 것 (그대로 지킴)
- 단어 퀴즈 없음. 순수 액션 게임, **판 수 무제한**. 코인은 **하루 상한까지만**(새 화폐 없음), 상한 뒤에는 기록 · 별 · 반 보스 피해만 쌓인다.
- 목적: 학생들이 앱을 **자주 다시 찾게** 하기. 진짜 재밌고, 박진감 있고, 퀄리티가 높아야 한다.
- 장르 재미(무리 불리기 숫자 문 · 숫자 장애물 사격 · 갇힌 영웅 구출 · 대포로 무리를 쏟아붓는 공성전 · 판 중간 카드 3장 중 1장)는 크라우드 러너 장르 일반을 참고한다.
  특정 게임의 그림 · 캐릭터 · 이름 · 생김새는 따라 하지 않고 **SUMUS 펫 세계(하늘 다리 · 정령 · 수정 · 성)**로 새로 만든다.
- 서버 요청은 **판 시작 · 끝 두 번뿐**. 서버가 조종 기록으로 판을 다시 돌려 결과를 정하고, 무리는 **숫자 하나**로만 계산한다.

## 1. 화면 흐름
```
놀이터 → [펫 대행진 입구]
  ├─ 오늘의 도전(반 공통 맵, 반 순위)      ← 하루 한 맵, 몇 번이든 도전, 최고 기록만
  ├─ 스테이지 지도 1 → 100(별 3개)         ← 테마 4개 × 25스테이지, 10마다 보스 성
  ├─ 주간 반 보스(반 전체 피해 합산 막대)
  ├─ 정령 강화(기존 코인)  · 도감 · 스킨
  └─ [출발] → 한 판(60~90초) → 결과(별 · 코인 · 보스 피해) → [다시] 한 번에 바로 다음 판
```
한 판 시간표(시험 페이지의 맵, 약 34초 — 실제 스테이지는 60~90초):

| 구간 | 시간 | 하는 일 |
|---|---|---|
| ① 달리기 | 0~18초 | 좌우 끌기로 조종. 숫자 문(+N · ×N · −N), 자동 사격으로 숫자 바위 깨기, 톱날 · 망치 피하기 |
| ② 카드 | 달리기 중 2번 | 규칙 시간이 멈추고 카드 3장 중 1장(정령 +N · 사격 ×1.5 · 방패 · 대포 위력 ×2 …) |
| ③ 구출 | 달리기 끝 무렵 | 수정에 갇힌 **내가 가진 펫**을 쏴서 구출 → 컷인 → 펫이 무리 앞에서 아레나 속성 필살기 |
| ④ 공성전 | 마지막 8~15초 | 대포 뒤에 무리가 모인다. **누르고 있는 동안** 정령이 쏟아져 성 HP를 깎는다. 성 HP 0 → 붕괴 → 별 1~3 |
| 결과 | 3초 | 별 · 남은 정령 · 코인(오늘 남은 만큼) · 반 보스 피해 → **[다시]** |

## 2. 규칙
### 2-1. 무리
- 무리 = **숫자 N 하나** + 가운데 좌우 위치 `cx`. 폭(반지름) `R = min(3, 0.4 + 0.21·√min(N,150))` — 품질(그리는 수)과 무관하게 N으로만 정한다.
- 조종: 화면을 좌우로 끌면 목표 `tx`가 움직이고, `cx`는 초당 10단위까지 따라간다(길 폭 ±4).
- 정령 하나하나는 **연출**이다. 화면에는 최대 150마리(품질별 40 · 70 · 110 · 150)만 그리고, 머리 위에 전체 숫자를 보인다.

### 2-2. 숫자 문
- 두 칸(왼쪽 · 오른쪽)이 한 쌍. 무리 가운데가 있는 칸 하나만 적용한다(동시 적용 없음 → 서버 판정이 단순).
- 연산: `+N`, `×N`, `−N`(0 밑으로 안 감). 좋은 문 파랑 · 나쁜 문 빨강. 통과하면 늘어난 정령이 문에서 날아와 붙고(불어나기), 줄어든 정령은 튕겨 날아간다.

### 2-3. 장애물 · 사격
- **숫자 바위**: HP = 숫자. 무리는 앞 26단위 안, 무리 폭과 겹치는 가장 가까운 줄을 **틱마다 자동 사격**한다.
  피해/틱 = `(0.6 + min(N,400) × 0.028) × 사격 배율`. 다 못 깨고 부딪히면 **남은 HP만큼 정령을 잃는다**.
- **톱날**: 길을 좌우로 오간다. 닿으면 `(1 + N×0.03) × 방패`만큼 잃고 0.15초 쉼.
- **망치**: 진자처럼 흔들려 바닥을 칠 때 그 자리에 있으면 `(2 + N×0.08) × 방패`.
- 깬 바위는 보상 숫자(+)가 뜨고 파편이 튄다(연출).

### 2-4. 카드(판마다 2번)
규칙 시간이 멈춘 동안 3장 중 1장. 카드 목록 초안(스테이지 씨앗으로 3장을 뽑음):

| 카드 | 효과 | 비고 |
|---|---|---|
| 정령 +20 / +30 / +50 | N에 바로 더함 | 스테이지가 높을수록 큰 수 |
| 정령 ×1.3 | N × 1.3(내림) | 늦게 고를수록 셈 |
| 사격 ×1.5 | 사격 배율 | 판 끝까지 |
| 관통탄 | 같은 줄 바위 모두에 같은 피해(기본) + 다음 줄에 50% | |
| 방패 | 톱날 · 망치 피해 ×0.5 | |
| 행운 문 | 다음 좋은 문 값 +50% | |
| 자석 | 깬 바위 보상 숫자만큼 정령 추가(+) | |
| 대포 위력 ×2 | 공성전에서 한 마리가 깎는 HP ×2 | |
| 연사 대포 | 공성전 쏟는 속도 ×1.5 | |
| 펫 각성 | 구출한 펫 필살기 범위 ×1.5 | |
| 수정 금 | 수정 HP −40% | 구출 쉬움 |
| 보스 사냥꾼 | 주간 반 보스 피해 +20% | 이번 판만 |

### 2-5. 구출 · 펫 필살기
- 수정(HP 숫자) 안에 **그 학생이 가진 펫** 중 하나(고른 대표 펫, 없으면 첫 펫). 깨면 컷인(1초, 규칙 시간 멈춤) 후 무리 앞에서 달린다.
- 펫은 **아레나 속성**대로 필살기를 한 번 쓴다(규칙은 숫자 하나로 판정):

| 속성 | 이름(예) | 규칙 |
|---|---|---|
| 불꽃 | 화염 돌파 | 앞 40단위 안 바위 모두 깨짐 |
| 물 | 물대포 | 앞 40단위 톱날 · 망치 멈춤 + 바위 HP −60% |
| 얼음 | 얼음 다리 | 6초 동안 모든 피해 0 |
| 풀 | 덩굴 그물 | 다음 나쁜 문을 같은 값 좋은 문으로 |
| 바위 | 바위 방패 | 다음 충돌 1번 피해 0 + 바위 HP −50% |
| 바람 | 돌풍 | 정령 +15% |
| 독 | 독안개 | 앞 바위 HP −70% |
| 별빛 | 별똥 | 공성전 성 HP −20% |

- 공성전 시작 때도 펫이 한 방(성 HP의 15%)을 친다.
- **펫 세기(CLAUDE.md 펫 세기 규칙)**: 필살기 효과 배율 기본 = 영웅 = 1.00, 전설 1.06, 신화 1.12(전설보다 약 +6%), 한정 1.00.
  ②단계에서 `server/runner-sim.mjs`로 "같은 스테이지 별 3 확률"이 등급 순서대로 약 6%씩만 차이 나는지 확인하고 검사에 넣는다.

### 2-6. 공성전 · 별
- 누르고 있는 동안 정령이 대포로 날아가고(초당 성 HP ÷ 6 정도, 최소 6 · 최대 `20 + N × 0.06`마리 → 공성전 약 6초), 한 마리 = 대포 위력(기본 1)만큼 성 HP를 깎는다. (v13.241에서 속도를 성 HP에 맞춤: 결과는 같고 길이만 정함)
- 성 HP 0 → 붕괴. 별: 남은 정령 / 공성전 시작 정령 ≥ 25% 별 3, ≥ 10% 별 2, 그 밖 별 1. 정령이 먼저 바닥나면 실패(별 0, 기록 · 보스 피해는 남음).
- 성 HP는 스테이지 곡선(아래 3장)으로 정한다. "얼마나 아껴 쏘나"보다 **문을 잘 골라 많이 불렸나**가 별을 정한다.

## 3. 숫자
### 3-1. 문 값 표(스테이지 s, 1~100)
| 구간 | 좋은 문 | 나쁜 문 | 쌍 구성 |
|---|---|---|---|
| 1~10 | +5~+15, ×2 | −3~−8 | 좋음/나쁨 쌍 70%, 좋음/좋음(더 큰 쪽 고르기) 30% |
| 11~40 | +10~+40, ×2, ×3 | −5~−25, ÷ 없음 | 좋음/좋음 40%(고르는 재미) |
| 41~70 | +20~+60, ×2~×3 | −10~−40 | 순서가 중요한 쌍(먼저 + 다음 ×) |
| 71~100 | +30~+80, ×2~×4 | −20~−60 | 좁은 길(장애물 사이로만 좋은 문) |

### 3-2. 스테이지 난이도 곡선
- 맵 길이: 1~10 = 60초, 11~50 = 75초, 51~100 = 90초(달리기 속도 10단위/초 고정).
- 기준 무리(잘 골랐을 때 공성전 시작 N) `Nref(s) ≈ 60 × 1.035^s` (1스테이지 ≈ 60, 50 ≈ 340, 100 ≈ 1,870).
- 성 HP `= Nref(s) × 0.55 × 대포 위력 기준(강화 평균)`. 잘 고르면 별 3, 한두 번 실수하면 별 2, 많이 실수하면 별 1.
- 바위 HP: 그 지점 기대 N × 0.3~0.8. 10의 배수 스테이지는 **보스 성**(HP ×1.5, 성 위 던전 몬스터 2마리 · 붕괴 연출 큼).
- 테마: 1~25 하늘 다리 · 26~50 사막 · 51~75 얼음 협곡 · 76~100 화산. 테마마다 장애물 하나씩 추가(사막 모래 소용돌이 · 얼음 미끄럼 · 화산 불기둥).

### 3-3. 정령 강화(기존 코인으로 영구)
| 강화 | 효과(단계마다) | 최대 | 값(코인) |
|---|---|---|---|
| 시작 정령 | +3 | 20단계(+60) | 20 + 10×단계 |
| 사격 | +4% | 20단계 | 20 + 10×단계 |
| 대포 위력 | +5% | 20단계 | 30 + 15×단계 |
| 방어 | 피해 −2% | 10단계 | 30 + 15×단계 |
| 다 올리는 데 | | | 약 1만 코인(학생 한 달 남짓) |
- 코인을 **쓰는 곳**이 생겨 코인 가치가 유지된다. 강화가 없어도 별 3은 가능하게(스테이지 곡선의 기준은 강화 절반).

## 5. 코인 하루 상한 제안
| 미니게임 | 하루 코인 상한 | 공부와 연결 |
|---|---|---|
| 인형뽑기 | 30 | 없음 |
| 사냥(별조각 → 코인) | 60 | 연습 보상 |
| 빈칸영작 | 70 | 공부 자체 |
| 낚시(진주 → 코인) | 100 | 미끼가 공부 보상 |
| 10초 맞추기 | 150 | 판 수가 공부로 늘어남 |
| **펫 대행진(제안)** | **40 + 첫 판 상자 10 = 50** | **없음(무제한 판)** |

- 순수 액션이고 판 수가 무제한이라 **공부와 묶인 게임보다 낮게**(인형뽑기 30과 사냥 60 사이). 판마다 별 1개 = 2코인, 처음 따는 별은 5코인(스테이지 100 × 별 3 = 300개라 처음 별은 오래 감).
- 하루 상한 뒤에는 코인 0, **기록 · 별 · 보스 피해 · 도감은 그대로** 쌓인다(재방문 이유는 코인보다 순위 · 보스 · 지도).

## 6. 서버 다시 계산 방식
### 6-1. 요청 두 번
| 요청 | 하는 일 | 크기 |
|---|---|---|
| `POST /api/runner/start` `{ mode: 'stage'|'daily', stage }` | 열린 판이 없으면 `open = { id, seed, mode, stage, at }`를 프로필에 적고 씨앗 · 맵 번호를 돌려준다. 맵은 화면이 씨앗으로 만든다(맵을 보내지 않음). | 응답 0.2KB |
| `POST /api/runner/finish` `{ id, input }` | 조종 기록으로 같은 판을 서버가 다시 돌려 별 · 남은 정령 · 점수를 정하고 저장. `open`을 지운다. | 요청 1~2KB |
| `GET /api/runner/home` · `GET /api/runner/board` | 지도 · 강화 · 오늘 코인 / 반 순위 · 반 보스. 1분 캐시 | |

### 6-2. 조종 기록(input)
- 틱(50ms)마다 목표 좌우 `tx`(−4~4를 −100~100 정수로) + 공성전 누름(0/1) + 카드 고른 번호 2개.
- 바뀐 틱만 적는다(`[틱, 값]` 쌍, 끌지 않는 동안은 없음) → 90초 판도 보통 0.5~1.5KB. 4KB를 넘으면 거절.

### 6-3. 다시 돌리기
- 규칙 코드는 화면과 서버가 **같은 파일**(`public/modules/runner-rules.js`, 아레나 `arena-rules.js`와 같은 방식)을 쓴다. 규칙 쪽 난수는 판 씨앗만 쓰고, 연출 난수와 섞지 않는다(시험 페이지에서 이미 나눔: `simRnd` · `rnd`).
- 무리는 숫자 N 하나 + `cx` 하나. 정령 하나하나 · 탄 · 파편은 서버에 없다. 90초 = 1,800틱 × 물체 30개 남짓 → **2ms 안쪽**(②단계에서 `check:load`로 확인).
- 막는 것: 한 번에 한 판만 열림(새 start는 열린 판을 버림, 하루 300판 상한) · 열린 지 10분 지난 판 무효 ·
  **너무 빨리 끝난 판 무효**(서버 시간으로 start → finish가 다시 돌린 판 길이의 90%보다 짧으면 0점) · 입력 틱이 판 길이를 넘으면 거절.
- 반 보스는 `runnerRaid[반].dmg += 이번 판 피해` 숫자 하나만 더한다. 순위는 GET에서 계산 · 캐시(쓰기 요청 안에서 다른 학생을 훑지 않음).

## 7. 데이터 묶음과 예산 (`server/perf-budget.mjs`에 넣을 안)
- 학생별(프로필 `games.runner`, 쌓이는 목록 없음):
  `{ st: 최고 스테이지, stars: '3321…'(스테이지마다 한 글자, 최대 100자), up: { s, f, c, d }, cd: 코인 날짜, ct: 오늘 코인, box: 상자 날짜, dd: { d: 날짜, b: 오늘 최고 }, rw: 받은 보스 주, open: { id, seed, mode, stage, at } | null }`
  → 학생 한 명 약 0.25KB, 90명이면 약 23KB. **기존 `profiles` 예산(1,500KB) 안**(묶음 새로 만들지 않음).
- 새 맨 위 묶음 하나:
  ```js
  runnerRaid: 10,   // 펫 대행진 주간 반 보스: 반마다 { w: 주 번호, dmg: 합계 } 숫자 둘(한 줄 약 0.05KB). 이번 주 · 지난 주만 남기고 지움.
  ```
- 오늘의 도전 맵 · 반 순위는 저장하지 않는다(맵 = 날짜 씨앗, 순위 = 프로필에서 GET 계산 · 1분 캐시).

## 8. 렉 방지 점검(규칙 8가지 중 해당)
| 규칙 | 지키는 방법 |
|---|---|
| 1. 보기는 GET | 지도 · 강화 · 순위 · 보스는 GET(`/home` · `/board`). POST는 start · finish · 강화 사기뿐 |
| 2. 요청한 학생 것만 | start · finish는 그 학생 프로필 + 반 보스 숫자 하나만 고침 |
| 3. 새 묶음 예산 | `runnerRaid` 10KB(이번 주 · 지난 주만). 학생 데이터는 프로필 안, 목록 없음 |
| 4. 무거운 계산은 GET에서 캐시 | 반 순위 · 반 보스 막대는 GET 1분 캐시. finish 안에서 다른 학생을 훑지 않음 |
| 5. 자동 새로고침 | 게임 중 서버에 묻지 않음. 입구 화면 보스 막대만 60초(화면 보일 때만) |
| 6. 실시간은 방 객체 | 실시간 없음(혼자 하는 판, 요청 두 번) |
| 7. 부하 상한 | 상한 그대로. ②단계에서 finish(다시 돌리기 포함)를 `check:load` 시나리오에 넣어 잰다 |
| 8. 연출 퀄리티 | 캔버스 한 장 · 정해진 풀 · 품질 자동 4단계(아래 측정) |
