# SUMUS QUIZ BATTLE V0.9.1.1 LIVE HOTFIX

Date: 2026-08-28

## P0 fixed

Physical iPhone testing exposed a timing regression not covered by the original E2E flow: if the teacher WebSocket connected before a new battle/lobby identity was created, the server could remain registered to the previous battle ID/code. The teacher then displayed a new Battle Code while students looked up a room the server had not registered, leaving the student on CONNECTING.

## Fix

- Teacher transport tracks the battle ID/code last confirmed by `SERVER_REGISTERED`.
- `TeacherBridge.publish()` ensures the current battle identity is registered before publishing its snapshot.
- WebSocket ordering makes registration precede the following snapshot on the same connection.
- Registration state is cleared on reconnect, close, and code collision.
- Student lookup no longer ignores a definitive `BATTLE_NOT_FOUND` for the entire 45-second cold-start window when the WebSocket is already live. Three live-server misses return to the code screen with a clear error.
- The existing cold-start retry remains for cases where the transport itself is not connected.

## Regression coverage

Added an E2E case that waits for the teacher WebSocket to establish before creating a new battle, then verifies a student can resolve the newly-created Battle Code.
